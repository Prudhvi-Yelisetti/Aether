## Key decisions

- **`ScriptMeta` is versioned identity metadata, never executable code-as-data.**
- **Model selection and capability selection are two separate calls.**
- **The Planner's decision prompt is built dynamically from the live registries**, not hardcoded.
- **`generate()` vs `generate_strict()`**: `generate()` for a human to read directly; `generate_strict()` for any automated caller checking success programmatically.
- **Validation and Decision are two separate concerns.**
- **The graceful fallback chain can hide total live-LLM failure indistinguishably from healthy degradation.** Check `experiences.tool_source` directly.
- **A new probabilistic check doesn't have to gate behavior on day one.** `validate_response_llm()` is observability-only until proven reliable.
- **Compose existing Steps into a new Skill rather than writing new logic.**
- **Not every Step's output is human-facing text.** `WriteFileStep` returns a string for the user; `SaveMemoryStep` returns structured data. The Skill→response boundary is where that gets bridged.
- **Labeling matters as much as content in a local-LLM prompt — but framing alone has limits.** Item 14 proved same stored rows + different framing = meaningfully different behavior. Item 20 then showed where framing wasn't enough: the real fix for memory bleed-through needed a structural split (semantic vs. episodic, with actual relevance-gated retrieval), not just better wording around one undifferentiated list.
- **A cognitive-science framework can be a genuine design tool, not just a metaphor, when it maps onto an actual bug.** Item 20's semantic/episodic memory split wasn't decorative — Tulving's distinction directly modeled which stored data should always be included (durable facts) vs. only cue-matched (specific past events), and "bounded capacity + graceful decay vs. total loss on overwrite" directly fixed a real behavior gap (episodic memory used to lose all history on every new skill run).
- **Check prior art before building from scratch, even for a metaphor-driven feature.** Items 21/22 were both checked against real reference implementations (Letta/MemGPT, Mem0, Zep, Generative Agents) before writing code — confirmed the two-tier memory shape and the sleep/reflection consolidation pattern were established designs, not something to reinvent.
- **An asymmetric-risk decision (fail closed vs. fail open) must be justified explicitly, not copied from the nearest similar feature.** Item 22's consolidation verifier fails closed because a bad write is *permanent* durable memory; `llm_validate` fails open because it only skips one observability check. The two features look similar (both are LLM-judged checks) but the right default is opposite for each, for a specific, statable reason.
- **Check what a gap statement itself claims before building to satisfy it.** Item 24: `ARCHITECTURE.md` said Tools lack the metadata Steps have via `ScriptMeta` — but `ScriptMeta` itself was missing 2 of the intended 6 fields. Building Tool/Skill to merely match Step's existing level would have closed the stated gap while leaving the real one (against the actual 6-field AI Object Model target) half-open.
- **A composed object's aggregate properties should be computed from its parts, not hand-duplicated onto it.** Item 24: a Skill's permissions are the union of its Steps' permissions, computed live in `describe_all()` rather than stored as a separate copy on the Skill — the copy would silently go stale the first time a Step changed without someone remembering to update the Skill too.
- **A shared parsing heuristic used by multiple callers can hide a real bug for a long time if none of them happen to trigger the failure shape.** Item 25: `extract_filename()`'s "first dotted word" heuristic had been silently wrong (matching quoted-sentence punctuation before a real filename) since it was written — `write_file` never happened to be tested with quoted content containing a period, `append_file`'s most natural test case (a journal entry) did. The bug wasn't new; the test case that could reveal it was.
- **A new interaction surface can expose bugs old tests never would.** Proven three separate times now: `execute_plugin()`'s missing branches (item 12), the AppRun shutdown bug (item 15, found by testing shutdown not startup), and the image timeout (item 16, found by Prudhvi's own independent real-world use, not a synthetic test).
- **An attached image or file skips Tool/Skill planning entirely** (`Plan(capability_type="reasoning", source="rule")`) — none of the current Skills know what to do with image bytes or inline file content, so letting the LLM planner route one into e.g. `calculate_and_explain` would be nonsensical rather than just wrong.
- **Libraries first, model capability as a fallback, not a bundled special-purpose dependency.** Item 17's PDF/DOCX decision: PyMuPDF/python-docx handle the common case exactly and instantly; the vision model (already tested, zero new binary dependency) handles the rare scanned-document case, instead of bundling Tesseract into a self-contained AppImage for something most documents don't need.
- **Check installed capability before choosing a design.** `GET /api/tags`'s `capabilities` field settled both the vision-model and PDF/DOCX questions before any code was written.
- **A synthetic test built by manually retyping a long encoded string is a real corruption risk.** Two hand-embedded copies of the same base64 string differed by 396 characters in item 16 — fetch real bytes instead whenever a test needs exact fidelity.
- **A dev frontend pointed at an already-built AppImage's backend produces confidently wrong results.** The squashfs bundle is frozen at build time regardless of what the frontend's env vars claim to be doing.
- **A fix for one Step's output shape doesn't cover every Skill sharing the same underlying defect class.** Item 26: fixing `SaveMemoryStep`'s dict-output content loss (stage 1) left an identical bug in `WriteFileStep`'s plain-string output completely unaddressed, because it never touched the code path stage 1 special-cased. A full audit — every Skill checked against the actual pattern, not just the one that prompted the investigation — found it; a narrower "fix this one case" pass wouldn't have.
- **A composed object's aggregate properties should be computed from its parts.** Reaffirmed by item 26's audit of item 24's design: a Skill's permissions are the union of its Steps', not a hand-duplicated copy — exactly the kind of thing a full audit is meant to catch if it had drifted, and confirmed it hadn't.
